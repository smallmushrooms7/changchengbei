## 几点收获

**OAuth 那道题的坑不在加密，在流程。** 题目给的 authorize 和 token 端点都「实现正确」，签名校验也没问题，问题出在 bind/callback 拿到 code 之后没有校验当前会话的身份，直接把会话切成了 code 对应的用户。这类缺陷扫描器扫不出来，只能顺着状态流转一步步走。

**LLM 应用的攻击面不在模型，在模型能调用的工具。** TicketSage 用小模型做意图分类，分类本身不难绕过，难的是绕过之后能干什么——它的 RAG 检索没有做权限过滤，工具里有一个读凭证库的函数。所以后来再看 LLM 应用，我先看它挂了哪些 tool，而不是先看 prompt。

**清内存马和找内存马是两件事。** 找的时候可以随便重启、随便杀进程；清的时候题目要求不中断服务，就得在运行态下把注入的 class 从内存里摘掉，同时保证业务还能跑。另外持久化后门往往不止一处，注册表、计划任务、启动脚本、被替换的 jar，要一处一处对。

**溯源最值钱的证据是时间差。** 日志里的时间、文件 mtime、进程的启动时间，三者对不上就是线索。这次是拿最早的异常访问对上了文件落地时间，再倒推攻击者第一次进来的时刻。
